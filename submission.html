Implementation Summary

All three tasks are implemented in plain HTML, CSS, and JavaScript — no frameworks, no build step, no external libraries. Each task folder opens directly in the browser. The implementation follows a consistent pattern throughout: update state → persist → re-render → update derived UI. Code comments explain the why behind each decision, not just the what.

Sortable Employee Table
styles.css  ·  table.js
CSS Changes — styles.css
ChangeReason / Decision
box-sizing: border-boxIndustry standard — padding and borders are included in element dimensions, preventing layout overflow. Consistent with Tasks 2 and 3.
Column widths via nth-childtable-layout: fixed was already set — nth-child is the correct selector. Widths: Name 28%, Dept 22%, Role 28%, Date 12%, Fee 10%

JavaScript Changes — table.js
ChangeReason / Decision
Currency symbol € in fee cellsRaw numbers without a unit are ambiguous in a data table — € makes the column self-explanatory
Implemented sortBy(key, type)Toggles direction on same key click, resets to asc on a new key
Stable sort via index tiebreakerEach row is tagged with its original array index. Equal values (e.g. same start date) preserve their original relative order
localeCompare for string sortHandles German umlauts (ä, ö, ü) correctly — plain < comparison would sort them incorrectly
Date.getTime() for date sortExplicit and unambiguous — makes intent clearer than lexicographic string comparison
.sort-arrow span injected per sortable headerLabel text node stays constant; only the empty span fills with ▲ or ▼ on sort. Column width is therefore never affected by the indicator being present or absent
classList.toggle('is-sorted') in setHeaderIndicators()Active column header receives a CSS class — blue accent applied entirely in CSS without inline styles or JS colour logic
Key Decision — Stable Sort
JavaScript's native sort is stable in all modern browsers. To make stability explicit and independent of engine guarantees, each row is tagged with its original index before sorting and that index serves as a tiebreaker when the primary comparison returns zero.
Fix — Horizontal Scroll Triggered by Sort Arrow
Appending "▲" to the header textContent caused "Monthly Fee ▲" to exceed the fixed 10% column width with white-space: nowrap, triggering a horizontal scrollbar. Fixed by: (1) injecting the arrow into an absolutely-positioned .sort-arrow span so it is outside the text flow and adds zero width, and (2) changing overflow: auto to overflow: hidden on the container.

Kanban Ticket Board — Drag and Drop
styles.css  ·  board.js
CSS Changes — styles.css
ChangeReason / Decision
cursor: grab on .ticketImmediately signals draggability before the user attempts to drag
Shadow lift on .ticket:hoverPhysical depth metaphor reinforces that cards can be picked up and moved

JavaScript Changes — board.js
ChangeReason / Decision
dragenter counter for highlightFixes the flicker bug: dragleave fires when the cursor moves into a child ticket element. A per-zone enterCount increments on dragenter and decrements on dragleave — highlight removed only when count hits 0
dragover calls preventDefault() onlyRequired by the HTML5 DnD spec to allow drops; highlight logic moved to dragenter/dragleave
drop resets enterCount to 0Ensures the counter is clean for the next drag even if dragleave didn't fire (e.g. fast drops)
dragend always clears stateFires even on Escape/cancelled drag — prevents stale ID affecting the next drag
setupDropzones() called once before render()render() only rewrites dropzone children — listeners survive re-renders without needing to be re-attached
Versioned localStorage keyIncrementing the version on schema change prevents stale data errors on load
el.dataset.priority = ticket.priorityExposes priority to CSS as a data-priority attribute — the badge colour is fully CSS-driven; zero JS colour logic needed
Bug Fixed — Drag-Over Highlight Flicker
Using dragover to add and dragleave to remove .drag-over caused visible flickering when the cursor moved over a child ticket card. Fixed with a dragenter/dragleave enter-counter: the highlight is removed only when the counter returns to zero — i.e. the cursor has fully left the column.
Key Decision — Module-Level Drag Variable vs. DataTransfer
A module-level draggedTicketId variable is simpler than DataTransfer: no serialisation, no parsing, intent is clear from the name. The only tradeoff — cross-window drops — is not a requirement here.

JavaScript Changes — map.js
ChangeReason / Decision
localStorage persistenceSelection survives page reload. loadSelection() validates each ID against current spotData — only spots that still exist and are available are restored
Implemented handleSpotClick(spot)All three rules in one place: ignore occupied → toggle selected → enforce max 3
Early return for occupied spotsNo state change, no re-render, no error — occupied tiles are purely informational
Deselect clears the error messageIf the user hit the limit then deselects a spot, the error is no longer relevant
Set for selectedIdsO(1) add/delete/has — more efficient than an array; also prevents duplicates without extra logic
Feature Added — Selection Persists on Reload
saveSelection() serialises selectedIds to localStorage after every interaction. loadSelection() runs before the first render and validates each saved ID — only spots that still exist and are still available are restored.
Key Decision — Full Re-Render on Every Click
With 10 spots the performance cost is negligible. A full re-render keeps the logic simple: selectedIds is the single source of truth and the DOM always reflects it completely. A partial DOM-update approach would be faster but harder to reason about.

Wichtige Entscheidung — Stabiles Sortieren
JavaScripts natives Sortierverfahren ist in allen modernen Browsern stabil. Um Stabilität explizit und unabhängig von Engine-Garantien zu gewährleisten, wird jede Zeile vor dem Sortieren mit ihrem ursprünglichen Index markiert. Dieser dient als Tiebreaker, wenn der primäre Vergleich null ergibt.
Behoben — Horizontales Scrollen durch Sortierungspfeil
Das Anhängen von "▲" an den Header-textContent ließ "Monthly Fee ▲" die feste 10%-Spaltenbreite bei white-space: nowrap überschreiten, was eine horizontale Scrollleiste auslöste. Behoben durch: (1) Einfügen des Pfeils in einen absolut positionierten .sort-arrow-Span (außerhalb des Textflusses, addiert keine Breite), und (2) Ändern von overflow: auto zu overflow: hidden am Container.

Behobener Fehler — Drag-over-Hervorhebung flackert
Die Verwendung von dragover zum Hinzufügen und dragleave zum Entfernen von .drag-over verursachte sichtbares Flackern beim Überfahren einer Kind-Ticket-Karte. Behoben mit einem dragenter/dragleave-Zähler: Die Hervorhebung wird nur entfernt, wenn der Zähler null erreicht — d.h. der Cursor hat die Spalte wirklich verlassen.
Wichtige Entscheidung — Modul-Variable vs. DataTransfer
Eine Modul-Variable draggedTicketId ist einfacher als DataTransfer: keine Serialisierung, keine Verarbeitung, der Intent ist am Namen ablesbar. Der einzige Nachteil — fensterübergreifende Drops — ist hier keine Anforderung.
